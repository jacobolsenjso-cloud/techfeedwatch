Jane Street, a leading quantitative trading firm, has developed a sophisticated suite of AI-powered coding assistants specifically designed for OCaml, a functional programming language that is powerful yet not widely adopted. This initiative addresses the significant gap in mainstream AI tooling for highly specialized development environments, showcasing a substantial commitment to enhancing developer productivity through custom-engineered solutions. Their approach, encompassing extensive data collection, tailored model training, and deep integration into developer workflows, offers a valuable blueprint for extending advanced AI capabilities to niche technological stacks.

## The Unique Challenges of OCaml Development

While OCaml is a highly capable functional language, its specialized nature presents considerable hurdles for leveraging off-the-shelf AI development tools. Unlike more common languages such as Python or JavaScript, OCaml lacks a vast public dataset for training large language models (LLMs), making general-purpose AI assistants less effective. Jane Street's internal OCaml codebase is likely larger than the combined public OCaml code available globally, highlighting the data scarcity problem.

Beyond the language itself, Jane Street operates a highly customized development environment that further complicates the adoption of standard AI tools. The firm has built its own build systems, a proprietary distributed build environment, and an internal code review system known as Iron. All software development occurs within a massive monorepo, which, unusually, is stored in Mercurial instead of Git. Furthermore, a significant share of the firm's developers—67% by last count—prefer Emacs over more commonly supported editors like VS Code. These bespoke choices, while optimizing for internal workflows, create a distinct ecosystem where generic AI solutions struggle to integrate or perform effectively. The firm also harbors an ambition to apply LLMs to diverse development tasks, from resolving merge conflicts to generating feature descriptions and suggesting code reviewers, requiring a level of flexibility and integration that off-the-shelf products typically do not offer.

## Crafting Bespoke Models from Internal Data

Recognizing these limitations, Jane Street embarked on a strategy to train custom AI models. An early inspiration came from Meta's Code Compose project, which successfully fine-tuned models for Hack, another language predominantly used within a single company. However, initial assumptions that simply exposing a foundational model to internal code would suffice proved incorrect. Effective model training requires examples that precisely match the desired output format. For Jane Street, the primary goal was to enable developers to describe a desired change in their editor and receive a suggested diff, potentially spanning multiple files (e.g., a `.ml` file, a `.mli` interface file, and a test file). These generated diffs needed to apply cleanly and have a high likelihood of passing type checks, ideally targeting changes up to 100 lines in length.

Collecting suitable training data for this specific task was a significant undertaking. Traditional sources like internal code review "features" (similar to pull requests) were found to be too broad; their descriptions were often multi-paragraph narratives, and the associated code changes typically ranged from 500 lines upwards, far exceeding the target diff size. Similarly, individual commits were often just checkpoints without clear descriptions and frequently bundled multiple unrelated changes.

The solution involved an innovative approach called "workspace snapshotting." Developer workstations are continuously monitored, with snapshots taken approximately every 20 seconds. Alongside code snapshots, the build status is also recorded. This allows the system to identify specific patterns, such as a transition from a "green" (passing build) state to "red" (failing build) and back to "green." These "green-to-red-to-green" sequences often correspond to an isolated change where a developer introduced a bug and then fixed it. By capturing the build error at the red state and the subsequent diff that restored the green state, valuable training data for error recovery and isolated changes can be extracted. To generate the natural language prompts for this data, an LLM was initially used to create highly detailed descriptions, which were then iteratively filtered down to mimic the concise, human-like prompts a developer might type in an editor. This process yielded the important "context, prompt, diff" examples needed for supervised training.

## Reinforcing Quality with the Code Evaluation Service

Supervised training is only one part of building high-performing code generation models; reinforcement learning (RL) plays a vital role in aligning model outputs with human notions of "good code." For OCaml, good code is defined by several criteria: it must parse correctly, pass the static type checker, compile successfully, and ultimately pass associated tests.

To facilitate this alignment, Jane Street developed a specialized "Code Evaluation Service" (CES). This service functions much like a highly optimized build system. It pre-warms a build environment to a known good (green) revision. Then, dedicated workers continuously receive diffs generated by the AI model, apply them to the pre-warmed environment, and immediately check if the build status remains green or turns red. This rapid feedback loop, sustained over months, allows the models to progressively learn to generate code that not only compiles but also passes tests. The CES setup is also instrumental for model evaluation; by holding out a portion of the RL data, the firm can objectively measure how well a model performs against these quality metrics. This rigorous evaluation is essential to prevent models from generating unhelpful or even "hilarious" outputs, as experienced with an early code review model that, when prompted, responded with "I'll do it tomorrow"—a reflection of human-like but undesirable behavior learned from training data.

## Integrating AI into the Developer Workflow

To make these custom AI capabilities accessible to developers, Jane Street created a dedicated "AI Development Environment" (AID). The design of AID prioritized three key principles: supporting multiple editors efficiently, maintaining architectural flexibility, and collecting comprehensive usage metrics. Given the firm's use of Neovim, VS Code, and Emacs, the goal was to avoid rewriting core logic for each editor.

The AID architecture employs a sidecar application model, where AID runs alongside the developer's editor on their local machine. This service acts as an intermediary, handling all the complex logic for constructing prompts, gathering relevant code context, and querying build status before interacting with the LLMs. Thin, editor-specific layers then integrate with AID. This decoupled design means that updates to AID—such as swapping in new models, refining context-building strategies, or adding support for new editors—can be deployed and restarted on developer machines independently of the editors themselves, ensuring that everyone receives the latest enhancements without manual editor updates.

The user experience is tailored to each editor. In VS Code, AID integrates as a sidebar, providing a visual interface for requesting and reviewing multi-file diffs, similar to other popular coding assistants. For Emacs users, who are accustomed to text-based workflows, the AID experience is presented within a markdown buffer. Developers can interact by typing questions, and keybinds append the AI-generated content directly into the buffer, allowing users to manipulate the output using their familiar Emacs commands. This flexible architecture also enables A/B testing of different AI models or strategies; for instance, 50% of developers might use one model while the other 50% use another, allowing the firm to measure acceptance rates and determine the most effective solutions.

## The Broader Implications of Tailored AI

Jane Street's investment in bespoke AI for OCaml underscores a growing trend in specialized industries: the necessity of tailored AI solutions where off-the-shelf tools fall short. By custom-engineering models and integrating them deeply into their unique development environment, Jane Street has not only boosted productivity for its OCaml developers but also established a strong, adaptable platform. This platform can incorporate new LLM advancements, support additional domain-specific tools, and extend AI capabilities to other complex workflows, such as multi-agent systems and advanced reasoning models. The firm's approach demonstrates that for niche languages, proprietary codebases, or highly customized development practices, a significant investment in custom AI development can yield substantial returns, offering a blueprint for other organizations facing similar challenges in bringing advanced AI to their specialized technological stacks.
